# {{kb_name}}

{{description}}

这里保存这个方向的原始资料、个人笔记和整理后的知识。你负责选择资料、写下想法和提出问题，Agent 根据来源整理知识页，并帮助维护索引、引用和分类。

如果正在公共模板目录阅读本页，先按[根使用手册](../../README.md#新建知识库)创建自己的知识库。下面的示例文件名可替换成你的实际文件名，路径以本库为起点；发给 Agent 时同时指明 `knowledge-base/{{kb_name}}`，避免操作到别的库。

## 从这里开始

- [知识索引](./wiki/index.md)：查看已整理页面及摘要。
- [综述](./wiki/overview.md)：阅读逐步积累的整体认识。
- [属性视图](./knowledge.base)：按属性浏览生成知识、人工笔记和类别。
- [操作日志](./wiki/log.md)：查看处理过的资料和维护记录。
- [按目的使用知识库](#按目的使用知识库)：复制并修改适合当前任务的请求。

## 目录与资料位置

```text
<本知识库>/                            # knowledge-base/<库名>/，只存本库内容
├─ README.md                           # 日常使用说明和 Agent 请求示例
├─ AGENTS.md                           # 摄入、引用、维护与交付的操作规则
├─ kb.toml                             # 本库目录映射，改布局时与说明一起更新
├─ knowledge.base                      # 本库的属性总览，在 Obsidian 中打开
├─ raw/                                # PDF、外部 Markdown、文本、图片等原始资料
│  └─ assets/                          # 资料附件，按需创建
├─ Clippings/                          # Web Clipper 保存的网页原文
├─ Notes/                              # 自己的笔记、想法和个人评价
│  └─ assets/                          # 笔记附件，粘贴或保存附件时按需创建
├─ wiki/                               # Agent 整理后的知识、分析和历史归档
│  ├─ index.md                         # 带摘要的知识目录
│  ├─ overview.md                      # 综合认识，随资料积累逐步形成
│  ├─ log.md                           # 摄入、保存、归档和体检记录
│  └─ bases/                           # 分类专用视图，建立分类入口时按需创建
├─ reports/                            # 批量摄入和体检报告
├─ templates/                          # 人工笔记、知识页、摘要、归档和分类的页面模板
│  └─ Bases/                           # 分类专用 Base 样板
├─ LICENSES.md                         # 模板来源与第三方许可
└─ .git/                               # 创建知识库时初始化的本地历史，公共模板不带此目录
```

| 资料类型 | 放在哪里 | 与知识页的关系 |
| --- | --- | --- |
| 可选中文字的 PDF、外部文章 `.md` 或 `.txt` | `raw/` | 读取原件，按内容新增或更新知识页。 |
| 扫描 PDF、照片、截图 | `raw/` | 识别后校对，提取稿与原件分开保存并相互对应。 |
| 网页剪藏 | `Clippings/` | 剪藏保存后再摄入，原件始终留在这里。 |
| 自己的读书笔记、想法和复盘 | `Notes/` | 继续由自己编辑；明确摄入时另建 raw 来源快照。 |
| 字幕或视频转写文本 | `raw/` | 记录视频来源和时间位置，再按文字资料摄入。 |
| 引用到的本地图片或其他附件 | 所属资料或笔记旁 `assets/` | 与所属库一起保留；远程图片不等于已离线保存。 |
| 整理后的概念、分析、资料摘要与分类入口 | `wiki/` | 从索引阅读，按来源持续维护。 |

原始资料处理后不会搬到“已摄入”目录；在索引和日志中查看处理结果。没有新增知识时，可能只增加一条日志。目录可以按库调整，实际以 `kb.toml` 为准；人工笔记统一使用 `Notes/`。详细约束见[内容所有权](./AGENTS.md#内容所有权)。

## 按目的使用知识库

单份资料先与 Agent 讨论要点和拟更新位置，讨论后可以回复“按刚才讨论的范围摄入”。已经明确的目标不必重复确认。下面的请求使用本库路径，文件名只是示例，发送前换成实际名称。

### 摄入有文字层的 PDF

把 `示例论文.pdf` 放入 `raw/`。你可以用 PDF 阅读器尝试选择文字；能选中通常表示有文字层，但仍需核对提取结果。

```text
在 knowledge-base/{{kb_name}} 中，阅读 raw/示例论文.pdf。
先与我讨论论文的主要问题、方法、结论和局限，以及哪些已有页面需要更新。
摄入时保留 PDF，重要结论注明页码；需要提取文字时另存提取稿并核对关键数字。
```

摄入后，从索引查看新增或更新的摘要、概念和分析，并通过来源链接回到 PDF 或提取稿。加密、缺页或提取乱码时，请 Agent 具体指出受影响部分；扫描页转到下面的流程，不用猜测补全。检查器无法直接验证 PDF 的文字，仍可能显示待核实提示，详见[检查与交付](./AGENTS.md#检查与交付)。

### 摄入扫描 PDF 或图片

把 `扫描报告.pdf` 或 `实验记录.png` 放入 `raw/`；下面以扫描报告为例，处理图片时替换文件名。

```text
在 knowledge-base/{{kb_name}} 中，先检查 raw/扫描报告.pdf 是否需要 OCR。
需要识别时使用当前可用的 local-ocr Skill，先检查服务是否可用。
保留原件，另存带页码对应的提取稿，复核表格、公式和关键数字。
先与我讨论可用内容和识别不确定处，再按确认的范围编译知识。
```

预期得到可追溯的提取稿，以及基于已核实部分的知识页。`local-ocr` 是可选本机工具，换电脑后不一定可用。缺服务、依赖或模型时，Agent 应说明具体缺项；你也可以提供已校对的文本版本。部分识别失败要保留并标明缺失范围，不能把整份资料算作已完整处理。转换和校对细节见[PDF 与图片资料](./AGENTS.md#PDF%20与图片资料)。

### 摄入外部 Markdown 或文本

把外部文章 `示例文章.md` 及其引用的本地附件放入 `raw/`，保持必要的相对路径。自己的笔记使用后面的 Notes 流程。

```text
请在 knowledge-base/{{kb_name}} 阅读 raw/示例文章.md。
先讨论它带来的新增知识、与已有资料的关系和可能的分歧，再按讨论结果摄入。
保留原件，引用实际来源；如果没有新增内容，记录原因即可。
```

有新增知识时，索引中会出现新增或更新页面，日志记录本次处理；没有新增内容时记为 `No material`。如果文章只剩链接、附件缺失或无法读取，先补齐需要的材料；Agent 不应把缺内容当作“没有新知识”。

## 使用 Obsidian Web Clipper

[Web Clipper](https://obsidian.md/zh/clipper) 是浏览器扩展。它将网页内容保存到 Obsidian，之后还需要你明确让 Agent 摄入；浏览器扩展中的剪藏模板与本库 `templates/` 的页面模板分别配置。

### 区分 Vault 名称与保存路径

以显示名称为 `obsidian` 的共享 Vault 和 `研究示例` 知识库为例：

| 字段或位置 | 应填写或对应的值 |
| --- | --- |
| Clipper 的 Vault 名称 | `obsidian`；替换为 Obsidian 实际显示的名称 |
| Vault 的磁盘根目录 | 本仓库根目录，可位于任意磁盘位置 |
| Folder / Note location 保存位置示例 | `knowledge-base/研究示例/Clippings` |
| 从 Vault 根目录定位剪藏文件夹 | `./knowledge-base/研究示例/Clippings` |

本库日常保存位置应使用 `knowledge-base/{{kb_name}}/Clippings`，或本库约定的实际映射。Vault 字段不填磁盘绝对路径、`knowledge-base`、子库名或 `knowledge-base-template/llm-wiki`。换电脑或重命名 Vault 后，以 Obsidian 实际显示的名称为准。

旧库尚无剪藏目录或映射时，先评估再按实际布局建立；本手册不代表已有库完成配置，也不授权自动迁移资料。目录调整见[分类入口与 Bases](./AGENTS.md#分类入口与%20Bases)。

### 保存网页并交给 Agent

1. 打开 Web Clipper 设置，确认已添加实际使用的 Vault（本例为 `obsidian`）。选择或复制一个剪藏模板，为目标知识库起清楚的模板名。
2. 将该模板的保存目标选为该 Vault，Folder / Note location 填 `knowledge-base/{{kb_name}}/Clippings`。Note name 可使用 `{{title}}`。
3. Behavior 使用 **Create a new note**，正文保留网页内容。重名时使用区分名称，不覆盖或追加到已引用的旧原件。
4. 保存前核对剪藏弹窗中的 Vault 和文件夹，以及网页正文、原始网址、作者、发布日期和剪藏日期。页面没有的信息不猜填。
5. 保存后在本库 `Clippings/` 找到文件，打开确认正文是否完整，再发送下面的请求。

```text
在 knowledge-base/{{kb_name}} 中，阅读 Clippings/示例网页.md。
先与我讨论值得积累的内容，再将新增知识编译到本库；保留剪藏原件和来源信息。
```

摄入后，知识页应能追溯到这份剪藏，原件仍留在 Clippings。若剪藏只有标题、导航或少量正文，可先选中需要的网页文字再剪藏，或调整该网站的剪藏模板。B 站等视频页面也要检查实际保存内容：页面文字不等于视频全文，需要视频内容时另行提供字幕或转写，并注明出处和时间位置。

### 出现 vault not found 时

按顺序核对：

1. **设置里的名称**：必须与 Obsidian 的 Vault 名称完全一致；本例为 `obsidian`，不是磁盘路径。
2. **剪藏弹窗里的选择**：当前选中的 Vault 是否仍是预期的 Vault。
3. **当前模板的目标**：模板是否仍指定旧 Vault，是否误选了另一个库的剪藏模板。
4. **保存路径**：Folder / Note location 是否为 Vault 内相对路径，用 `/` 分隔，不使用盘符或绝对路径。

重新保存后，以目标目录中出现文件且内容可打开为成功标志。仍失败时，把 Vault、保存位置、所用模板名和错误原文交给 Agent 排查。先区分“找不到目标 Vault”和“网页内容没剪完整”，两者处理方法不同。

以上配置与排错依据[官方模板说明](https://obsidian.md/help/web-clipper/templates)和[官方排错说明](https://obsidian.md/help/web-clipper/troubleshoot)，查阅日期为 2026-11-16。官方也提供选中文字或高亮后重新剪藏的内容缺失处理方法。

## 使用自己的笔记

### 新建笔记与整理位置

在 Obsidian 中右键本库 `Notes/` 新建笔记，插入“人工笔记模板”，再写自己的内容。当前全局快捷键的新建位置是 Vault 根目录，不会自动识别所属知识库。也可以请 Agent 准备一张空白笔记：

```text
在 knowledge-base/{{kb_name}}/Notes/ 新建“读书想法.md”，使用人工笔记模板。
只准备必要属性和空白写作位置，正文由我填写；同名文件不要覆盖。
```

如果已经写好的 `读书想法.md` 错放在本库顶层，可以请求：

```text
将 knowledge-base/{{kb_name}}/读书想法.md 整理到本库 Notes/，修复受影响链接，
按人工笔记模板补齐缺失属性；保留正文观点和已有属性，不猜填未知信息。
```

结果应是笔记位置正确、已有链接仍能打开、你的内容保持原意。重名、所属库不清或涉及其他库的链接时，Agent 应列出具体问题供你决定，不直接覆盖。详情见[内容所有权](./AGENTS.md#内容所有权)。

### 在笔记中创建并嵌入 Excalidraw 绘图

前提是 Excalidraw 已安装并启用；未安装时先按根手册确认恢复范围，不为本例自动安装。以本库 `Notes/读书想法.md` 为例：

1. 从本库 Notes 打开或新建笔记，切到编辑视图，将光标放在准备插图的独立空行。
2. 在命令面板选择 **Excalidraw: 新建绘图 - 于新标签页 - 并嵌入到当前 Markdown 文档中**（英文界面名称包含 “Create new drawing” 和 “embed into active document”）。该命令同时建立绘图和笔记嵌入。
3. 在新标签页绘图并保存，回到原笔记检查是否显示绘图；同时在文件列表核对实际文件路径。当前共享配置使用笔记旁的 `assets/`，因此预期文件位于 `Notes/assets/`，名称通常带笔记名和时间。必要的图片等附件也须核对归属。

“嵌入时使用 Excalidraw 文件夹”关闭时，插件采用 Obsidian 的附件目录；当前附件配置为 `./assets`。这与普通“新建绘图”命令不同：普通新建使用插件配置的绘图目录，当前为 Vault 根级 `Excalidraw/`，不能假设会跟随当前 Notes。此区别可核对[上游设置说明](https://github.com/zsviczian/obsidian-excalidraw-plugin/blob/master/src/lang/locale/en.ts)。

若实际路径不符，先检查这两项设置及当前笔记所属库，不删除绘图、不自动改共享配置。需要整理位置时，明确目标库后在 Obsidian 内移动并复核嵌入链接；有同名或跨库引用时先确认。全局新建笔记快捷键的落点另见上一节，不能用来判断绘图落点。

### 把个人笔记编译为知识

以 `Notes/读书想法.md` 为输入。需要把其中内容纳入知识体系时，明确说出要摄入的笔记：

```text
在 knowledge-base/{{kb_name}} 中，将 Notes/读书想法.md 的内容整理为知识页。
先讨论适合积累的内容；摄入时在 raw 保存注明原路径和日期的来源快照，
保留必要附件，原笔记继续留在 Notes。区分我的个人判断与有外部证据的事实。
```

预期得到一个 raw 来源快照，以及引用该快照的知识页和操作记录。以后继续编辑 Notes 不会自动改写旧快照；再次要求摄入时形成新快照，再比较更新知识。附件缺失或某项外部事实缺依据时，先标出问题，不替你补造来源。具体过程见[个人笔记摄入快照](./AGENTS.md#个人笔记摄入快照)。

新快照记录原笔记路径和摄入时的修改时间。现行知识仍引用该快照，而原笔记时间发生变化时，只读检查会按原笔记提示可能需要重新摄入；复制或 Git 检出也可能触发提示，需阅读比较后决定。旧快照缺少这些可选字段仍可使用，不批量补写。

## 批量处理与更新知识

### 批量摄入待处理资料

把要处理的资料放好后，明确范围。以下请求只包括本库 raw 和 Clippings，不会顺带摄入所有个人笔记：

```text
批量摄入 knowledge-base/{{kb_name}} 的 raw/ 和 Clippings/ 中尚未处理的资料。
逐份串行处理，不逐份等待我确认；保留原件和来源分歧，无法读取的文件先跳过并说明原因。
完成后更新索引和日志，在 reports/ 给出处理结果、疑点和待确认事项。
```

预期得到更新后的知识索引和一份批量报告。已记录为无新增内容的资料无需反复处理；新增提取稿与对应原件作为同一来源理解，避免重复生成知识。遇到不可读文件，可继续处理其他资料，但报告须列明跳过项，不能称为全部成功。

### 用新资料更新旧认识

把新资料 `新版研究.md` 放入 raw，保留原有来源：

```text
在 knowledge-base/{{kb_name}} 阅读 raw/新版研究.md，先讨论它对已有结论的影响。
按讨论结果摄入时，更新所有受影响的生成知识，并保留真实分歧及各自来源。
说明哪些旧结论被明确取代，哪些只是不同条件下的结果；保留重要历史依据。
```

结果应体现在有关知识页、综述、索引条目与摘要和日志中，而不只多出一份孤立摘要。日期保留在页面属性中，不在索引重复维护。新来源发布时间较晚并不自动推翻旧来源；证据不足时应保留争议或待核实说明。个人笔记和已归档答案不会随这次更新改写。

## 提问、保存与归档

| 目的 | 发给 Agent 的请求示例 | 会得到什么 |
| --- | --- | --- |
| 只想理解已有知识 | “根据 knowledge-base/{{kb_name}}，比较目前记录的两种研究方法，说明依据和适用条件。只回答，不保存。” | 对话中的带引用答案，不新增文件或日志。 |
| 想持续完善这份分析 | “将刚才的比较保存为 knowledge-base/{{kb_name}} 的分析页，便于以后继续更新。” | 新的分析页，并更新索引和日志；以后参与知识维护。 |
| 想保留当时的回答 | “把刚才的比较归档到 knowledge-base/{{kb_name}}，保留今天的判断作为历史快照。” | 注明日期的归档页，以及索引和日志记录；以后不随知识更新重写。 |

提问的依据是本库已积累的资料，Agent 应先查索引和全文。找不到答案时应说明缺口，不用模型记忆冒充本库知识。若要补充外部研究，另行明确提出；需要修改已有分析时直接指定页面，避免误建同主题的新页。来源更新后，归档页可能提示已过时，但仍保留历史内容。格式细节见[查询、保存与归档](./AGENTS.md#查询、保存与归档)。

## 检查并整理知识库

资料积累后，遇到失效链接、目录不好找或怀疑某些结论过时，可以发起一次体检：

```text
请体检并整理 knowledge-base/{{kb_name}}。
依据原文修复生成知识的结构、索引、链接和确有依据的内容问题，保留真实来源分歧。
个人笔记只整理位置、缺失属性和受影响链接，保留观点；资料空白只提出研究建议。
复查后给出 reports/ 报告，并在日志中链接它。
```

预期得到具体的修复清单、改动页面和剩余问题。没有可靠依据、链接有多个可能目标或需要跨库处理时，应说明原因并等待必要决策，不猜测修复。

如果只想运行结构检查，先按[根使用手册](../../README.md#环境)准备环境，再从共享仓库根目录的终端执行：

```shell
uv run --no-sync python scripts/check_kb.py "knowledge-base/{{kb_name}}"
```

检查器只读，不会替你修文件。退出码 `0` 为无检查发现，`1` 为有错误或待核实事项，`2` 为配置或运行失败。看到结果后阅读具体提示：未处理资料、PDF 未解析和疑似数值不匹配含义不同；通过也不代表所有事实均已核实。处理方法见[检查与交付](./AGENTS.md#检查与交付)。

人工待建链接会列为待核实，短双链按页提醒实际解析范围尚未核验；它们不会因此自动被删除或创建。日志与报告的断链仍按严格导航检查。常用完整、折叠引用式 Markdown 链接可参与检查，复杂语法仍须实际打开验证。目录不可读时返回 `2`，先处理该路径的读取问题，再重新检查。

## 按需建立独立分类入口

先用本库 `knowledge.base` 总览浏览已有内容；希望围绕一个类别给出导读、阅读顺序或专用字段时，再建立分类入口。例如已有若干方法类知识页：

```text
在 knowledge-base/{{kb_name}} 为已有的方法类知识建立“方法”分类入口。
给出导读和阅读顺序，配置专用 Bases，默认只展示本库生成知识。
保留全库总览，更新索引和日志，并验证其他库同名内容不会混入。
```

预期得到 `wiki/方法.md` 和 `wiki/bases/方法.base`，从分类入口即可浏览成员页。分类不必覆盖所有内容，也不必预装书影音等生活类别。想纳入人工笔记时，明确指定展示范围；展示不意味着允许 Agent 改写笔记。

总览固定绑定本库；“现行知识”和“按类别浏览”隐藏 `status: empty` 的空综述，填写后移除该状态即可显示；综述文件及本页入口始终保留。现行知识与历史归档分开显示，分类专用 Base 也提供“历史归档”视图。公共样板未绑定、跨库嵌入或未知上下文应为空。先到实际知识库内打开，再核对成员分类和绑定路径；不要删除范围过滤来“修复”空表。手工复制总览须填完三个绑定占位符，遗漏会提示 `base-binding-missing`。库改名、改映射和旧库升级的顺序，以及分类占位符、属性、过滤和验证步骤见[分类入口与 Bases](./AGENTS.md#分类入口与%20Bases)。

## 页面模板的三种用法

| 用途 | 操作入口 | 影响范围 |
| --- | --- | --- |
| 共享 UI 插入 | 命令面板的 Templates 从公共 `knowledge-base-template/llm-wiki/templates` 读取，并替换标题、日期等变量。 | 修改公共模板会影响所有库此后的插入；只在已确认的全局变更范围内修改。 |
| 本库人工或 Agent 创建 | 手工复制本库 `templates/` 正文并填写变量，或明确让 Agent 读取本库模板创建页面。 | 本库副本不是 Templates 插件的自动入口；单库定制不默认同步公共目录。 |
| 独立迁出参考 | 保留本库 `templates/` 副本，在迁出时按新 Vault 配置入口。 | Bases、属性双链和共享工具仍需适配；副本不自动跟随公共模板更新。 |

新来源模板的 `source_url` 保存来源 URL，`collected` 记录收集日期，`published` 记录已知发布日期。Clipper 原件中的 `source` 与 `clipped` 分别保留其来源与剪藏时间含义，不改名、不统一改写属性类型。它们都不同于生成知识的 `sources` 原始资料路径列表。

## 规则与版本历史

操作细节集中在本库 [AGENTS.md](./AGENTS.md)，共享环境和多库边界在[根 AGENTS.md](../../AGENTS.md)。本库页面模板副本位于 `templates/`，用法见[三种入口说明](#页面模板的三种用法)；需要调整目录时，同时更新映射、说明和引用，不只移动文件夹。

本库使用独立本地 Git，默认不设置远端、不上传。可以用历史记录查看知识如何变化；重要旧结论和归档仍按规则保留。正文相对引用可以随库迁移；单独迁出共享 Vault 时，Bases、属性双链和共享工具入口需要相应调整。

模板更新不会自动覆盖本库内容；共享 Templates 入口会影响此后插入的页面，共享检查器升级可能产生新的待核验提示。旧库升级先逐项比较映射、规则和绑定，按[分类入口与 Bases](./AGENTS.md#分类入口与%20Bases)完成检查后再使用，不覆盖人工内容。上游参考 Base 可能查询整个 Vault，参考页面的分类型 `type` 须先适配为本仓库文本页面类型及 `categories` 列表，不直接混入共享属性约定。第三方模板来源与许可见 [LICENSES.md](./LICENSES.md)。
