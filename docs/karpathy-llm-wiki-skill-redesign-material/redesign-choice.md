## 实现约定

2026-11-17 经三份 LLM 反馈与源码反例核对后，用户确认以下增量选择，仅应用到公共工具、模板、相关文档和规则，已有私有库不迁移：

- 总览固定绑定所属库根和目录映射，生成知识限定 wiki，人工笔记限定 Notes；跨库及未知上下文为空。现行知识与历史归档分视图，初始化自动绑定，人工复制显式填写占位符。
- 人工缺失链接统一列为 `REVIEW`，短双链按页提示实际解析范围未核验；不搜索其他库。生成知识、索引、日志与报告保持严格导航检查。常用单行定义、完整和折叠引用式 Markdown 共用解析结果，代码及引用定义路径不进入证据候选。
- 新人工笔记快照记录原笔记的相对路径及带引号的 `st_mtime_ns`。现行知识引用该 raw 快照时，检查器按原笔记汇总可能更新提醒；不计算哈希，不改写原件、快照或知识页，旧快照字段保持可选。
- 插件恢复同时检查 `manifest.json` 与 `main.js`，残缺插件可在授权安装范围内补装，保留 `data.json` 原字节；不卸载或批量升级完整插件。本轮只用模拟 CLI 测试，不安装真实插件。
- 根级 assets、Clippings 加入忽略，提供按需运行的只读路径检查；不安装提交钩子，不移动、删除或暂存用户内容。检查器均保持 `0/1/2` 退出码约定。
- 补齐辅助 Skills 的仓库格式优先级、共享 Templates 对未来插入的影响、上游 Base/属性兼容说明及 Excalidraw 从 Notes 创建并嵌入的操作。独立 Vault 迁出教程留作另行任务。

> 这些选择是本轮批准的实现方向，不把 LLM 报告当作权威结论或额外授权。反馈原文保持不变；实际结果见[本轮验收记录](./review-followup-validation.md)。

2026-11-16 补充选择：用户经常使用 Obsidian Web Clipper，融合模板独立保留 `Clippings/`。它与 `raw/` 同属原始资料层，剪藏摄入后保留原位；默认按库隔离，不在 Vault 根建立共享剪藏目录。增加可选 `paths.clippings` 映射，旧库无需强制升级，已有资料不自动移动。这是结合 Steph 剪藏用途与用户工作流的新增选择，不改变不预装完整生活分类的决定。Clipper 是可自定义保存路径的浏览器扩展，目录名称并非插件强制要求。

- 每库用 kb.toml 记录可变目录；Notes 固定。来源路径是文档相对路径列表；正文提供可点击相对引用。
- managed_by 明确生成内容的维护权限，未标记已有内容按人工内容保护。
- 检查器只读，退出码 0 无发现、1 有发现、2 配置或运行失败；“待核实”不等于事实错误，机械匹配不等于完整事实验证。
- 初始化不覆盖已有库，不复制上游 Git 元数据和 Obsidian 配置。支持人工复制、改名、填写 README、git init。
- 保留用户原有修改，按阶段本地提交；与上游原件保持分离。规则修改需用户批准。
